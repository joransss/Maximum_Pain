\# Maximum Pain — Project Instructions



\## Project

Maximum Pain is a multiplayer third-person shooter in Roblox inspired by Max Payne 3.



\## Sources of truth

\- Obsidian Vault/: game design, requirements, roadmap, architecture and testing documentation.

\- Roblox Studio: actual game implementation and current state.

\- CLAUDE.md: permanent working rules for Claude.



\## Workflow

1\. Before implementing a feature, read the relevant Obsidian specification and architecture notes.

2\. Inspect the existing Roblox project before making changes.

3\. Implement one milestone or feature at a time.

4\. Reuse existing code and systems. Avoid unnecessary abstractions, duplicated logic and excessive token usage.

5\. Keep competitive gameplay server-authoritative. Validate weapon firing, ammunition, hit results and damage on the server.

6\. Test changes in Roblox Studio whenever possible.

7\. Never publish the game unless explicitly instructed.

8\. Do not rewrite unrelated systems when implementing a feature.

9\. Ask before making destructive changes or when requirements conflict.



\## Documentation updates

After completing a milestone:

\- Update the relevant roadmap task.

\- Record implemented systems and important architecture decisions.

\- Record tests performed, failures and outstanding issues.

\- Distinguish verified functionality from functionality that has not been tested.



Keep documentation concise. Do not load the entire vault for every task; read only relevant notes.



\## Completion report

After each task, report:

\- What changed

\- Where it changed

\- What was tested

\- Remaining issues

\- Which documentation was updated
